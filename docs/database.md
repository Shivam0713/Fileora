# Database notes

MongoDB stores `users`, `sessions`, `otp_challenges`, `files`, and `jobs` documents. User records contain normalized email, display name, role, verification status, auth version, salted scrypt password hash, and timestamps. Session records contain a hash of the signed JWT and a hash of its `jti`, user id, and expiry; raw tokens are never stored. OTP challenge records contain a hash of the opaque challenge id, an HMAC of the OTP, purpose, pending/verified/used/locked status, attempt count, resend and expiry timestamps, and only the flow data required to finish registration or recovery. Reset grants are stored hashed and single-use. File records include account or anonymous-session owner, safe display name, format, size, opaque storage key, creation/expiry timestamps, and output status. Job records include owner, source file id, tool slug, validated options, state, timestamps, and output id or sanitized error. Unique indexes cover user email, session token/JWT id, OTP challenge ids, and reset-grant hashes; TTL indexes expire sessions and OTP challenges. Owner/creation history and source-job indexes support cleanup and reads. Celery Beat removes expired local files or R2 objects before deleting corresponding metadata every 15 minutes.
