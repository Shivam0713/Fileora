# Security status

Implemented: registration is pending until a six-digit email OTP is verified; password login also requires an email OTP; forgot-password uses a verified one-time reset grant and revokes all sessions. OTPs are HMAC-hashed with a server-only secret, expire after five minutes, allow five attempts, and have a 60-second resend cooldown. Redis fixed-window limits apply by hashed email and client IP, and authentication fails closed if Redis is unavailable. Email is sent using Resend or TLS-protected SMTP (for example, Brevo); codes are not returned by the API or included in logs. Passwords use salted scrypt hashes. Authentication uses an HS256 JWT in the HTTP-only SameSite=Lax cookie and MongoDB hashed session references for revocation. Admin role checks and owner-scoped file/job access remain in place. An administrator is seeded from `ADMIN_EMAIL` and `ADMIN_PASSWORD` and is marked verified by provisioning. Other protections include opaque ObjectId storage keys, private storage outside the frontend/public tree, server-side format/tool/options checks, bounded streaming upload, Pillow content decoding, fixed operation/format mapping, and output verification. User-controlled filenames are reduced to a basename and used only as download display names.

Production deployment still requires HTTPS with `SESSION_COOKIE_SECURE=true`, secret-manager injection for JWT/OTP/email credentials, trusted proxy configuration so IP rate limits use the real client address, email-domain verification, monitoring and alerting for delivery failures, security headers/CSP, malware scanning, per-file quotas, comprehensive media/archive-bomb protections, and operational backups. The Redis limiter uses fixed 15-minute windows. The local Compose services are for development, not a production deployment.
